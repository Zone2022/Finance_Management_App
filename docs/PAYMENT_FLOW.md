# 支付通知与智能分类

## 通知导入

Android `NotificationListener` 只处理已知来源的通知，并把标题和正文交给 `PaymentParser`。解析器只匹配明确的支出格式；收入、退款、失败通知和其他应用消息不会入账。未匹配的已知来源在 `DiagnosticLog` 记录状态，但不记录通知正文、金额或账号。

识别成功后，`PaymentQueue` 将事件暂存在本机。Flutter 的 `NotificationHandler` 在启动、回到前台或收到通知信号时读取队列，依次完成分类、数据库写入和确认删除。数据库按事件 ID 防止同一事件重放产生重复数据。

银行通知和支付平台通知可能属于同一笔交易，但它们没有共同的可靠交易号，当前不会跨来源自动合并，需在流水中核对。监听服务未收到的通知无法由队列补回。

## 智能分类

`ClassificationService` 首先查询本地商户规则；没有匹配时调用 `AiService`。空或未知商户直接归为“其他”。`AiService` 只调用设置页中选定的服务，验证返回的分类属于应用支持的类别；请求失败时回退到“其他”。

DeepSeek 与 Claude 的 Key 及当前选择通过 `flutter_secure_storage` 保存在设备安全存储中。设置页只展示是否已保存，不回显原值；替换或删除需打开对应配置弹窗。商户名称会发送给选定的外部服务，通知正文不会作为提示词发送。保存 Key 仅表示已写入本机，并不代表服务端认证已经成功。

## 排查

在“设置 → 运行日志”先检查通知使用权和监听连接状态，然后发一笔小额测试支付并刷新日志。如果没有相关日志，检查系统通知是否真的弹出、使用权是否授予以及手机厂商的后台限制；如果显示格式未匹配，需要记录脱敏样例以扩展 `PaymentParser`。日志最多保留 200 条，可手动清空。

DeepSeek 和 Claude 符号来自 Simple Icons，详见 `assets/brands/README.md`。应用的运行日志不包含 API Key。
