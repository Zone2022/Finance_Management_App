# 个人财务管理应用使用指南

适用版本：1.0.0+1；依据 GitHub 提交 `8e8df305f2b21db005d8f6c5009f348b2fe62e4f` 的实际代码编写。编写日期：2026-09-30。

## 1. 这款应用可以做什么

这是一个以 Android 为主要目标的本地支出记录原型。它监听支持格式的微信、支付宝支付通知，将识别到的支出保存到手机本地，并展示流水、当月汇总和年度图表。无需注册账号，也没有自建服务端或云同步。

当前仍有金额识别和重复入账风险，适合试用、开发验证。重要支出请与微信/支付宝官方账单核对。安装成功不代表通知识别已经通过真机验收。

| 功能 | 当前情况 |
| --- | --- |
| 自动记账 | Android 通知监听；仅处理符合规则的通知 |
| 支出分类 | 内置商户关键词；可选 DeepSeek AI |
| 流水查询 | 按类别、微信/支付宝来源筛选 |
| 汇总报表 | 本月支出、日均支出、交易笔数、分类占比、年度月度趋势 |
| 手动新增、修改、删除流水 | 没有界面入口 |
| 自定义分类、编辑商户规则 | 没有界面入口 |
| 历史账单导入、导出、备份恢复 | 没有界面入口 |
| 收入、退款、转账及多币种管理 | 没有完整业务流程；金额统一按人民币展示 |
| iOS、Windows、Web | 不能视为完整可用版本；自动通知记账仅在 Android 实现 |

## 2. 安装与启动

### 已有安装包

1. 使用项目维护者提供、来源可信的 Android APK。
2. 按手机系统提示允许该安装来源，安装后打开应用。系统应用名称目前是 `flutter_finance`，应用内显示「个人财务」。
3. 首次打开没有记录时，流水显示「暂无交易记录」，报表显示「暂无数据」，属于正常情况。
4. 若提示「本地数据库无法打开」，先检查剩余存储空间，再点击「重试」。不要通过清除应用数据来排障，否则可能丢失账本。

本次未构建或验证 APK；仓库源码本身不是可直接安装的文件。

### 从 Windows 源码运行

需要 Flutter、Android Studio/Android SDK 和 Android 手机或模拟器。项目声明 Flutter >=3.44.0、Dart >=3.12.0 且 <4.0.0；原有文档记录曾使用 Flutter 3.44.9 / Dart 3.12.2，本轮未复验该工具链。

在 PowerShell 中执行：

```powershell
Set-Location "C:\Users\24190\Projects\flutter_finance"
flutter --version
flutter doctor -v
flutter doctor --android-licenses
flutter pub get
flutter analyze
flutter test
flutter devices
```

将下面的设备 ID 替换为 `flutter devices` 列出的 Android 设备：

```powershell
flutter run -d <Android设备ID>
```

如果找不到 `flutter`，将实际 Flutter SDK 的 `bin` 目录加入 PATH。真机需开启开发者选项、USB 调试并接受电脑授权；不要选择 Windows 或 Chrome 来验证本项目的自动记账。

需要调试安装包时执行：

```powershell
flutter build apk --debug
```

输出位于 `build/app/outputs/flutter-apk/app-debug.apk`。正式版要求配置发布签名，见 [部署与测试流程](DEPLOYMENT_TESTING.md)；不要把签名密码、keystore 或 API Key 上传到仓库。

## 3. 首次开启自动记账

1. 打开底部「设置」。
2. 在「自动记账」区域点击「打开通知使用权设置」。
3. 在系统列表中找到本应用并开启通知读取权限，确认系统提示。
4. 返回应用，并确保微信/支付宝允许显示支付通知。
5. 在正常支付后返回应用，打开「流水」核对金额、商户和时间，再检查「概览」是否更新。

通知使用权与普通的“允许应用发送通知”不是同一种权限。如果入口无法打开，可在系统设置中搜索“通知使用权”或“通知读取权限”。不同手机菜单名称可能不同。

支持的通知目前必须同时满足：

- 来源应用是微信或支付宝。
- 标题恰为「微信支付」「支付宝」或「支付宝支付」。
- 正文包含「支付成功」「付款成功」或「消费成功」。
- 正文不包含「退款」「收款成功」「收入」「失败」「待支付」。
- 金额符合解析器当前格式，且为正数；分组汇总通知会被忽略。

这不是直接读取官方账单。没有产生通知、授权前未被采集、标题/文案不兼容或监听服务未工作时，交易可能漏记，应用不能自动补齐历史账单。也不应假定全部带“支付成功”的通知都能被正确识别。

应用界面未运行时，监听服务若仍正常工作，事件会先暂存；重新打开应用后再导入数据库。系统强制停止应用、关闭权限或限制后台运行时，不能保证继续采集。

## 4. 查看概览

底部「概览」提供：

- **本月支出**：本月已保存的支出合计。
- **日均支出**：从本月 1 日到今天（含今天）的支出，除以已经经过的自然日数；包括没有消费的日期。
- **交易笔数**：本月交易记录数。
- **查看全部流水**：跳转到流水页。

例如本月截至 10 日共支出 300 元，日均为 30 元，而不是除以实际消费的天数。统计使用设备本地时间；自动流水时间取通知发布时间，不是支付平台订单时间。

可以下拉刷新。页面也会在数据库写入或应用回到前台时尝试刷新；如果出现「数据加载失败，请重试」，点击「重试」。

## 5. 查询交易流水

1. 点击底部「流水」。
2. 用「全部类别」选择餐饮、交通、购物、居住、娱乐、医疗、教育、通讯或其他。
3. 用「全部来源」选择微信或支付宝。
4. 两个筛选可组合使用；分别选回「全部类别」「全部来源」可恢复全部流水。

记录按时间从新到旧排列，显示商户名称、来源、月/日和时分、金额及分类图标。当前没有日期范围筛选或关键词搜索，时间标签也不显示年份。

「未知商户」表示通知里未解析到商户名称；没有匹配规则或 AI 分类失败时，类别通常是「其他」。

点击流水目前不会打开编辑页。若发现漏记、重复或金额不正确，当前界面无法补录、纠正或删除；请保留官方账单和脱敏通知样本交给维护者，不要把显示合计当作最终对账结果。

## 6. 使用统计报表

底部「报表」包含：

| 图表 | 含义 |
| --- | --- |
| 本月支出分类 | 当前自然月各类别占比 |
| 月度支出趋势 | 所选年份 1～12 月支出的柱状图 |
| 年度趋势 | 同一个所选年份的月度支出折线图，并非多年的年度总额比较 |

年份下拉可选择当年及前四年；它同时影响柱状图与折线图，不改变上方“本月”饼图的月份。已有年度数据时，没有记录的月份按 0 显示；完全没有数据时显示「暂无数据」。

纵轴中的 `k` 表示千元，例如 `1.0k` 为 1,000 元。饼图目前只有颜色和百分比，没有类别文字图例；可以参考「设置」中的分类颜色，但这是当前可读性限制，已列入审查报告。

## 7. 配置可选 AI 分类

不配置 API Key 也可以使用本地分类和记账。内置关键词例如「美团」对应餐饮、「滴滴」对应交通、「京东」对应购物。

需要 AI 时：

1. 打开「设置 → AI 分类设置」。
2. 输入有效的 DeepSeek API Key。
3. 点击输入框右侧的保存图标，看到「AI 设置已应用（仅本次运行）」。
4. 后续未匹配本地规则、且不是空白或「未知商户」的商户名，会尝试发给 DeepSeek 分类。

分类顺序为本地规则 → 可选 AI →「其他」。AI 请求超时设置为 5 秒；请求失败、Key 错误或返回非预设类别时会回退。界面没有专门的 Key 连通性测试，点击保存不代表 Key 已验证有效。

Key 仅保存在本次进程内存中，进程重启后需重新输入。暂时切换到后台不一定会清除 Key。清空输入框并点击保存可停用后续 AI 调用。

成功得到的非「其他」AI 分类会保存成本地商户规则，以后可能直接复用；关闭 AI 不会删除这些规则，也不会重分类已保存的交易。

## 8. 数据与隐私

交易与商户规则保存在设备本地 SQLite 数据库 `finance.db`；等待导入的通知事件先保存到应用私有暂存区。应用没有自己的账户或云同步功能，也没有提供用户可操作的导出、迁移或备份恢复入口。

启用 AI 后，代码会把未匹配的商户名称发送到 DeepSeek；该分类请求不包含交易金额和完整流水。通知读取权限本身属于较广的系统权限，当前代码仅处理微信/支付宝来源。

卸载应用、清除应用数据或换手机均可能导致无法找回账本。更新尽量使用相同应用 ID、同一签名的覆盖安装；签名冲突时，不要为了安装新版直接卸载唯一存有账本的旧版。开发者排查和备份方法需要单独设计，系统备份不能视作本应用提供的可靠恢复能力。

## 9. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 支付后无记录 | 核对通知读取权限、支付应用是否实际发出通知、通知格式及系统后台限制；回到应用等待导入 |
| 下拉刷新仍没有记录 | 下拉刷新只重新查询数据库，不会拉取微信/支付宝历史账单 |
| 显示「其他」 | 本地没有匹配、商户未知、未开启 AI 或 AI 调用失败均可能导致 |
| 重启后 AI 不工作 | 重新输入 Key 并点击保存；进程重启不保留 Key |
| 流水为空但之前有数据 | 先清除类别/来源筛选；再检查是否重装或清除了应用数据 |
| 金额错误或同一笔出现多次 | 本轮已确认存在相关识别/去重风险；对照官方账单，当前没有界面修正入口 |
| 报表年份切换后饼图没变 | 饼图固定为本月，年份仅影响下方两个趋势图 |
| 安装正式版提示签名配置缺失 | 按部署文档创建本地签名配置；临时开发验证可以构建 Debug 包 |
| Windows/Web 启动数据库失败 | 当前生产数据库未为这些目标配置实现，请使用 Android 验证 |

## 10. 建议的首次验收

先用测试设备或非唯一账本进行验证：检查空页面 → 授予权限 → 核对一笔正常支出 → 切换筛选 → 查看汇总 → 返回后台再回到前台核对补录 → 检查是否重复。AI 可以在基础链路验证后再开启。
